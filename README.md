# nitro-fan — управление вентиляторами и мощностью Acer Nitro AN515-55 под Linux

**Русский | [English](README.en.md)**

![License](https://img.shields.io/badge/license-MIT-green)

**nitro-fan** — набор инструментов, возвращающих тихое и осмысленное управление
охлаждением ноутбука **Acer Nitro 5 (AN515-55)** под Linux:

- **nitro-fan.sh** — CLI: CPU-режимы (тихий / баланс / полная мощность),
  фиксация скорости вентиляторов, EC-диагностика (чтение регистров, live-тесты),
  шаблоны systemd-юнитов;
- **nbfc-quiet-curve.json** — тихая конфигурация кривых вентиляторов для
  [NBFC-Linux](https://github.com/nbfc-linux/nbfc-linux) по раскладке EC, проверенной live на этой машине;
- **nitro-gui.py** — GTK3-приложение: статус (температуры, RPM, EPP), переключение
  режимов, ручная фиксация скорости, графический редактор кривых, иконка в трее.

## 1. Как вентиляторами управляет матплата

На Nitro 5 всё охлаждение целиком ведёт встроенный контроллер EC (Embedded Controller,
«встроенная микропрограмма матплаты», чип Stonic_CMS, BIOS V2.06). Linux к нему
напрямую не обращается: прошивка сама следит за температурой CPU/GPU/NVMe и крутит
два вентилятора по заложенным кривым. Известные регистры EC этого поколения
(подтверждены community-конфигами для AN515-44/AN515-54):

| Назначение                     | EC-адрес |
|--------------------------------|----------|
| CPU fan: RPM read / speed write| 0x13 / 0x37 |
| GPU fan: RPM read / speed write| 0x15 / 0x3A |
| CPU fan manual mode            | 0x22 = 0x0C (каждая запись скорости заново) |
| GPU fan manual mode            | 0x21 = 0x30 (каждая запись скорости заново) |
| Global manual mode             | 0x97 = 0x01 |
| CoolBoost (NitroSense overdrive)| 0x16 (0 = выкл) |

Ключевая особенность: EC периодически сбрасывает «ручной режим», поэтому
нужен периодический повтор записей (это и делает NBFC-сервис / наш скрипт).

## 2. Что сейчас видит Linux (факты с этой машины)

- hwmon: **ни одного** `pwm*`/`fan*` интерфейса → `fancontrol`/`pwmconfig` бесполезны.
  Не видно даже RPM вентиляторов.
- Датчики: coretemp (Package до 77°C под нагрузкой), acpitz 61°C, PCH 49°C,
  NVMe 32°C, iwlwifi 39°C; GPU по nvidia-smi 53–55°C.
- thermald активен (тротлинг CPU в защиту), governor intel_pstate=powersave.
  power-profiles-daemon: пользователь выбрал профиль «Баланс»; поверх него
  работает оверлей `cpu-quiet` (EPP=balance_power + потолок 2600 МГц).
- `/sys/firmware/acpi/platform_profile` отсутствует — стоковый модуль `acer_wmi`
  этот ноутбук не регистрирует (profilesдаёт Linuwu-Sense, см. ниже).

## 3. Тихий режим — что выбрано

Двухуровневый путь:

**A. Работает уже сейчас (уменьшает шум без записи в EC)**
- Профиль `balanced` вместо `performance`;
- EPP `balance_power` вместо `performance`;
- потолок частоты CPU 2600 МГц (вместо 5000). Пиковый ток 6 ядер i7-10750H —
  главный источник шума; ограничение заметно охлаждает при обычной работе.
- Всё это делает `sudo ./nitro-fan.sh cpu-quiet on` (обратимо, state сохраняется).
  Сохраняемый звук остаётся под управлением EC по его стоковым кривым — безопасно.
  `on` также включает автозагрузку юнита; `off` — выключает её, поэтому «полная
  мощность» (`powerprofilesctl set performance` + `cpu-quiet off`) переживает ребут.

**B. Управление вентиляторами (NBFC-Linux)**
Тихая двуступенчатая кривая (рекомендованные значения):

| | CPU fan | GPU fan |
|---|---|---|
| старт вращения | 55°C → 20% | 50°C → 20% |
| тихий ход | 60–65°C → 25–32% | 55–60°C → 25–30% |
| обычный | 70–75°C → 40–55% | 65–70°C → 40–55% |
| разгон | 80°C → 72%, 85°C → 90% | 75°C → 72%, 80°C → 90% |
| max | 90°C → 100% | 85°C → 100% |
| аварийно (скрипт) | ≥87°C → 100% | ≥83°C → 100% |

Эти числа мягче стоковой кривой NBFC (которая стартует с 12% уже при 42°C —
на этой модели вентиляторы слышно всегда) и заметно тише прошивочной кривой
(Nitro держит сравнительно высокие обороты от ~45–50°C), но не позволяют
перегреву: thermald продолжает защищать CPU, а скрипт ставит 100% по
аварийным порогам.

## 4. Графическое приложение nitro-gui.py

GTK3 (python-gi, есть из коробки). Запуск: из меню приложений «Nitro: вентиляторы
и мощность» (ярлык и иконка кладутся в ~/.local/share при первом запуске) либо
`python3 ~/nitro-fan/nitro-gui.py`. При закрытии окна остаётся в трее (иконка
с быстрым меню режимов).

- **Статус** — CPU/GPU температуры и RPM, профиль PPD, EPP, потолок частоты,
  выбранный конфиг NBFC; обновление каждые 2 с.
- **Режимы** — три кнопки: Тихий / Родной баланс / Полная мощность.
  Тихий и Полная мощность используют pkexec (диалог polkit); спид-скорости —
  без пароля (сокет NBFC 0666).
- **Вентиляторы** — фиксация скорости (nbfc set -s), авто-возврат,
  редактор кривой 9 порогов 50–90°C × 2 вентилятора + пресеты «Тихий»/
  «Динамичный»; «Применить кривую» строит конфиг «Acer Nitro AN515-55 Custom»
  и ставит его pkexec'ом один раз. Настройки кривой сохраняются в
  ~/.config/nitro-fan/curve.json.
  На вкладке «Статус» шкалы загрузки вентиляторов окрашены по зонам безопасности
  (тихая/нагрузка/тротлинг) в приглушённые зелёный/жёлтый/красный.
- **Автозапуск приложения** — чекбокс на вкладке «Режимы»: ставит/убирает
  ~/.config/autostart/nitro-fans.desktop (при логине приложение стартует
  свёрнутым в трей — иконка с режимами всегда под рукой).
- **О программе** — кнопка ⓘ в шапке окна: версия, лицензия, ссылка на репозиторий.

## 5. Скрипт nitro-fan.sh

```
./nitro-fan.sh status                 # температуры, профиль, EPP, потолок
./nitro-fan.sh watch [сек]            # то же в цикле
sudo ./nitro-fan.sh cpu-quiet on      # тихий CPU-режим (работает уже сейчас)
sudo ./nitro-fan.sh cpu-quiet off     # откат
sudo ./nitro-fan.sh cpu-quiet-apply 2600000   # то же без сохранения state (для автозагрузки)
./nitro-fan.sh fan-speed 30           # задать скорость (NBFC установлен)
./nitro-fan.sh fan-auto               # вернуть профиль NBFC
./nitro-fan.sh fan-curve              # тихий демон с аварией → 100% и возвратом auto
./nitro-fan.sh install-nbfc           # пошаговая установка NBFC-Linux
./nitro-fan.sh unit                   # systemd-юнит для автозапуска fan-curve
./nitro-fan.sh unit-cpuquiet          # systemd-юнит автозапуска cpu-quiet
./nitro-fan.sh ec-prep / ec-read / ec-test [сек] / ec-max / ec-sweep
```

**Автозагрузка (установлено):** `nitro-cpu-quiet.service` — oneshot юнит,
копия скрипта в `/usr/local/bin/nitro-fan`; после старта
`power-profiles-daemon` применяет EPP=balance_power + потолок 2600 МГц.
Проверка/управление: `systemctl status/restart/disable nitro-cpu-quiet`.

**Защита от дрейфа (установлено):** `nitro-cpu-quiet-assert.timer` раз в
5 минут прогоняет `cpu-quiet-assert` — перезаписывает тихие значения, если
профиль был изменён извне (например, переключателем профилей в трее
Cinnamon). Если `nitro-cpu-quiet` отключен (режимы «Родной баланс» /
«Полная мощность»), таймер бездействует. Шаблоны юнитов: `./nitro-fan.sh
unit-timer`.

Скрипт версия: `./nitro-fan.sh --version` (синхронизирована с файлом
VERSION в репозитории).

## 6. NBFC-Linux — установлено и работает

Установлен nbfc-linux 0.5.4 (deb для Mint 22 — в ~/Downloads).

- Конфиг: «Acer Nitro AN515-55 Quiet» (json-копия — nbfc-quiet-curve.json).
- Сенсор GPU-вентилятора привязан к max по ядрам (`nbfc sensors set -f 1
  -s coretemp -a Max`): NVML-источник (`nvidia-ml`) в сборке не подхватывается.
- Сервис: `nbfc_service.service` — enabled + active (write-режим),
  ec_sys грузится с указанных модулей-правил:
  /etc/modprobe.d/ec_sys.conf (`options ec_sys write_support=1`),
  /etc/modules-load.d/ec_sys.conf (`ec_sys`).

```
nbfc status -a        # обороты/цели (nbfc status -a -w 3 — живой монитор)
nbfc set -s 40        # обе фанаты на 40%
nbfc set --auto       # вернуть профильную кривую
sudo systemctl start/stop/restart nbfc_service
```

Проверка live (17.11): в автолежании NBFC пишет CPU 0 → EC отпускает и держит
свой прошивочный пол (~2000 RPM), GPU ~20-25% — тоже прошивочный пол (~2300).
Звук такой же, как в стоке, но при нагреве кривая улинит по нашей кривой:
55°→20%, 60–65°→25–32%, 70–75°→40–55%, 80°→72%/85°→90%, 90°→100%.

Нюанс: пока NBFC в write-режиме, НЕ запускать ec-* команды скрипта —
NBFC перекорректирует вручную.

Файл конфига основан на проверенной раскладке EC этого поколения Nitro 5
(AN515-54: CPU 0x13/0x37, GPU 0x15/0x3A, manual-режимы 0x22/0x21/0x97,
CoolBoost 0x16). Для AN515-55 офконфиг в репозитории NBFC отсутствует —
зато AN515-44/-54 (та же платформа Comet Lake-H) исторически совпадают.

Альтернатива NBFC: ядро-модуль [Linuwu-Sense](https://github.com/0x7375646F/Linuwu-Sense)
(DKMS, заменяет `acer_wmi`): добавит `fan_speed`, лимитаторы батареи, RGB и
`/sys/firmware/acpi/platform_profile` (quiet/balanced/performance) для Nitro.
Ставится по его README; интерфейс Nimbus: `echo 50,70 | sudo tee .../nitro_sense/fan_speed`.

## 7. Безопасность

- `fan-curve` перехватывает SIGINT/TERM/EXIT и возвращает вентиляторы в `--auto`.

### 7.1 Результаты live-тестов на этом устройстве (17.01, BIOS V2.06)

- `ec-read`/`ec-test`/`ec-max`/`ec-sweep` (nitro-fan.sh): раскладка EC AN515-55
  полностью совпала с AN515-44/-54; manual-биты литчатся (12/48/1), duty в
  0x37/0x3A работает (100% → RPM CPU 2013→5172, GPU 2325→6122, что ровно
  MaxSpeedValueRead=6122 из конфига).
- **Полная остановка невозможна**: duty=0 прошивка трактует как «release → auto»
  (поэтому в NBFC-конфигах FanSpeedResetValue=0), а малые duty (≤~40) EC
  подтягивает к своему прошивочному минимуму ≈ 2000–2350 RPM — тот же
  «тихий» уровень, что и в авто-режиме. Кулеры Nitro AN515-55 в принципе не
  останавливаются прошивкой (совместимо с наблюдениями владельцев: ни NBFC,
  ни Linuwu-Sense не могут заглушить кулеры этого поколения полностью).
- После ec-* тестов `ec_sys` остаётся загружен (write_support=1); писать может
  только root (io 0600). Отключить: `sudo rmmod ec_sys`.
- Записи в EC повторяются только сервисом NBFC; ручных «сырых» poke'ов нет.
- Если фан-управление после неудачных экспериментов зависло (вентиляторы не вернулись):
  полный power-off (отключить БП и вытянуть батарею на 2–3 мин) сбрасывает EC.
- thermald и прошивочные датчики остаются действуют поверх всего этого.
